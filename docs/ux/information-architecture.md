# البنية المعلوماتية (Information Architecture) — منصة توا

> **مصدر الحقيقة:** `docs/requirements/توا-المتطلبات.pdf`. هذه بنية **مقترحة** مبنية على المتطلبات حصراً؛ أي إضافة موسومة **[افتراض]** أو **[توصية]**. لا تتناول هذه الوثيقة الشكل البصري إطلاقاً (مرحلة لاحقة في `docs/design/`).

المنصة ثلاث تجارب منفصلة تماماً في الملاحة والصلاحيات:

1. **لوحة تحكم التاجر** — تطبيق خلف تسجيل دخول
2. **واجهة المتجر للزبون** — موقع عام على النطاق الفرعي لكل متجر، دون حسابات
3. **لوحة مدير المنصة** — تطبيق خلف تسجيل دخول إداري

## 1. لوحة تحكم التاجر

### 1.1 الملاحة الأساسية (Primary)

| البند | يغطي البنود |
|---|---|
| الرئيسية (نظرة عامة) | تجميع مؤشرات **[توصية — لا يوجد بند «لوحة إحصائيات» صريح في المتطلبات]** |
| الطلبات | 1.5.2 – 1.5.5 |
| المنتجات | 1.4.1 – 1.4.8 |
| المخزون | 1.4.9 – 1.4.12 |
| الخصومات | 1.5.1 |
| المظهر والقوالب | 1.3.1 – 1.3.5 |
| فريق العمل | 1.5.7 – 1.5.9 |
| إعدادات المتجر | 1.2.2 – 1.2.5، 1.5.6 |

### 1.2 الملاحة الثانوية

- **قائمة المستخدم (أعلى الشاشة):** الملف الشخصي وحالة التوثيق (1.1.6)، تعديل البيانات (1.1.7)، تغيير كلمة المرور (1.1.5)، تسجيل خروج.
- **داخل «إعدادات المتجر» (تبويبات):** عام (اسم/شعار/وصف 1.2.3) · النطاقات (1.2.2) · اللغة (1.5.6) · النشر (1.2.4 – 1.2.5).
- **داخل «المظهر» (تبويبات):** القوالب (1.3.1 – 1.3.2) · تخصيص الألوان (1.3.3) · ترتيب الأقسام (1.3.4) · زر معاينة دائم (1.3.5).
- **خارج الملاحة:** معالج الإعداد الأولي (1.2.1) يظهر مرة واحدة بعد التفعيل قبل دخول اللوحة.

### 1.3 الشاشات الرئيسية وإجراءاتها

| الشاشة | الإجراءات الرئيسية |
|---|---|
| معالج الإعداد الأولي | اسم المتجر، اللغة، حجز النطاق (تحقق فوري)، إنهاء نحو اللوحة |
| الرئيسية | قراءة مؤشرات، الانتقال السريع للطلبات/المخزون، رؤية حالة الاعتماد/النشر **[توصية]** |
| قائمة المنتجات | بحث/تصفية بالفئة والحالة، منتج جديد، تعديل، أرشفة، عرض |
| نموذج منتج (إضافة/تعديل) | بيانات أساسية، صور، تسعير، تفعيل متغيرات، توليد تركيبات، تحرير سعر/مخزون/صورة لكل تركيبة، حذف تركيبة، حفظ |
| المخزون | تعديل يدوي للكميات، رؤية المحجوز والصافي، ضبط حد التنبيه **[سؤال مفتوح: من يحدد الحد؟]** |
| قائمة الطلبات | تصفية بحالات الطلب/الدفع/التوصيل، فتح تفاصيل |
| تفاصيل الطلب | نقل الحالة (مؤكد → قيد التجهيز → جاهز → مسلّم)، إلغاء مع إرجاع المخزون، قراءة بيانات الشحن والرسوم |
| الخصومات | إنشاء خصم (مبلغ ثابت، فترة، حد أدنى)، تعديل/إيقاف **[افتراض: الإدارة اللاحقة للخصم غير منصوصة]** |
| المظهر — القوالب | استعراض، تثبيت/تغيير بنقرة |
| المظهر — الألوان | ضبط الألوان والخلفيات، معاينة |
| المظهر — الأقسام | ترتيب/إظهار/إخفاء بنرات وعروض وتصنيفات |
| فريق العمل | دعوة بالبريد، تحديد صلاحيات، تعديلها، تعطيل حساب |
| إعدادات المتجر | تعديل البيانات، حالة النطاق، اللغة، نشر/إلغاء نشر |
| الملف الشخصي | عرض حالة التوثيق، تعديل الاسم/الهاتف (مع OTP جديد عند تغيير الرقم)، تغيير كلمة المرور |

### 1.4 الحالات المهمة

| الحالة | أين تظهر وما تعرضه |
|---|---|
| فارغة | لا منتجات («ابدأ بإضافة أول منتج» + زر) · لا طلبات · لا خصومات · لا موظفون — دائماً مع إجراء البدء **[توصية]** |
| تحميل | هياكل بديلة (skeletons) للجداول والبطاقات **[توصية]** |
| خطأ | فشل جلب/حفظ مع إعادة محاولة؛ أخطاء حقول فورية في النماذج (هاتف مستخدم، نطاق محجوز) |
| غير مصرّح | موظف بلا صلاحية على شاشة → رسالة «غير مصرّح» مع مخرج آمن (1.5.8) |
| حالات وضعية | «بانتظار اعتماد الإدارة» · «المتجر غير منشور/صيانة» (1.2.5) · «حساب معلّق من الإدارة» (م.1.3.4) — شريط حالة دائم أعلى اللوحة **[توصية]** |

## 2. واجهة المتجر للزبون

### 2.1 الملاحة الأساسية

| البند | يغطي |
|---|---|
| الرئيسية (واجهة المتجر بأقسامها المرتّبة من التاجر 1.3.4) | 2.1.1 |
| التصنيفات (رئيسية → فرعية) | 2.1.3 |
| البحث | 2.1.2 |
| السلة | 2.2.1 – 2.2.4 |
| تتبع طلبي | 2.2.8 |

**لا يوجد حساب زبون** — لا تسجيل دخول ولا «حسابي» (2.2.8 صريحة: دون الحاجة لتسجيل الحساب).

### 2.2 الملاحة الثانوية

- **الفوتر:** صفحات السياسات (المذكورة في 1.2.4 و2.1.5)، بيانات تواصل المتجر (1.2.3). **[توصية]** إشارة «متجر على منصة توا».
- **داخل صفحة المنتج:** أقسام الوصف والسياسات وخيارات الشراء (2.1.5).

### 2.3 الشاشات الرئيسية وإجراءاتها

| الشاشة | الإجراءات الرئيسية |
|---|---|
| الرئيسية | تصفح الأقسام، الانتقال لتصنيف/منتج، بحث |
| قائمة منتجات / نتائج بحث | بحث فوري، تصفية فئة، فلترة سعر (أدنى/أقصى) ولون ومقاس، فتح منتج |
| صفحة المنتج | تصفح الصور، اختيار المتغير (مع تعطيل غير المتوفر)، تحديد كمية، أضف للسلة |
| السلة | تعديل كمية مع تحقق فوري من المخزون، حذف عنصر بنقرة، رؤية الإجمالي، إتمام الشراء |
| بيانات الشحن والدفع | إدخال العنوان والهاتف ومكان الاستلام، اختيار كاش/بطاقة، الانتقال لشاشة معاملات البطاقة عند اختيارها |
| تأكيد الطلب | رؤية رقم التتبع الفريد، نسخه، الانتقال للتتبع أو مواصلة التسوق |
| تتبع الطلب | إدخال رقم الطلب + الهاتف، رؤية مسار الحالة |
| صفحة الصيانة | تظهر عند إلغاء نشر المتجر (1.2.5) — بلا إجراءات |

### 2.4 الحالات المهمة

| الحالة | التفصيل |
|---|---|
| فارغة | سلة فارغة (+ زر متابعة التسوق) · لا نتائج بحث/فلترة (+ مسح الفلاتر) |
| نفاد/توفر | «غير متوفر» وتعطيل الإضافة عند نفاد الكمية · رسالة «المتاح X فقط» عند تجاوز الكمية (2.2.2) |
| خطأ | فشل تأكيد الطلب أو معاملة البطاقة → رسالة واضحة مع إبقاء بيانات النموذج **[توصية؛ سلوك فشل الدفع سؤال مفتوح]** |
| تتبع بلا تطابق | «لا يوجد طلب مطابق — تأكد من الرقمين» |
| متجر غير متاح | صفحة صيانة (إلغاء نشر) · **[سؤال مفتوح]** ما يُعرض لمتجر محظور من الإدارة |

## 3. لوحة مدير المنصة

### 3.1 الملاحة الأساسية

| البند | يغطي |
|---|---|
| الرئيسية (نظرة عامة) | تجميع مؤشرات وقوائم انتظار **[توصية]** |
| طلبات الاعتماد | م.1.3.1 – م.1.3.3 |
| المتاجر | م.1.3.4 – م.1.3.7 |
| فحص المنتجات | م.1.3.8 – م.1.3.9 |
| باقات الاشتراك | م.1.3.10 – م.1.3.12 |
| سجل التدقيق | م.1.3.13 |

### 3.2 الملاحة الثانوية

- **داخل «طلبات الاعتماد»:** تبويبات حالة (بانتظار المراجعة / مرفوضة / معتمدة مؤخراً) **[توصية]**.
- **داخل «المتاجر»:** فلاتر حالة (نشط / معلّق / محظور).
- **داخل «باقات الاشتراك»:** الباقات النشطة · المؤرشفة · التجديدات اليدوية.
- **قائمة المستخدم:** حساب المدير، تسجيل خروج. **[سؤال مفتوح]** هل يوجد أكثر من مدير وبمستويات صلاحية مختلفة؟ المتطلبات صامتة.

### 3.3 الشاشات الرئيسية وإجراءاتها

| الشاشة | الإجراءات الرئيسية |
|---|---|
| طلبات الاعتماد — قائمة | فرز بالأقدمية، فتح طلب للمراجعة |
| طلب اعتماد — مراجعة | فحص البيانات وعرض الوثائق، اعتماد وتفعيل، رفض مع سبب إلزامي |
| المتاجر — قائمة | بحث، فلترة حالة، معاينة متجر، تعليق/فك تعليق، حظر |
| معاينة متجر | رؤية واجهة المتجر كما يراها الزبون (م.1.3.7)، اتخاذ إجراء رقابي |
| فحص المنتجات | تصفح المنتجات عبر كل المتاجر مع فلترة بالمتجر والحالة، وسم سليم، حظر وإزالة مع سبب ودليل يُرسل للتاجر |
| باقات الاشتراك | إنشاء باقة (خدمات/حدود/سعر)، تعديل، أرشفة، تجديد اشتراك تاجر يدوياً بعد السداد |
| سجل التدقيق | قراءة العمليات الحساسة مع فلاتر (النوع/التاريخ/المنفّذ) **[توصية للفلاتر]** — بلا أي تحرير |

### 3.4 الحالات المهمة

| الحالة | التفصيل |
|---|---|
| فارغة | لا طلبات اعتماد معلّقة («أنجزت كل المراجعات») · سجل تدقيق بلا نتائج ضمن الفلتر |
| تحميل | هياكل بديلة للقوائم والجداول **[توصية]** |
| خطأ | فشل تنفيذ إجراء رقابي → رسالة مع إبقاء الحالة كما كانت وإعادة محاولة |
| تأكيدات خطرة | الاعتماد، الرفض، الحظر، الإزالة — نوافذ تأكيد بسبب إلزامي حيث نصّت المتطلبات (م.1.3.3، م.1.3.9) |
| غير مصرّح | وصول غير إداري لأي مسار إداري → رفض كامل |

## 4. ملاحظات معمارية عابرة للتجارب

1. **الفصل الكامل:** لا رابط ملاحي بين التجارب الثلاث؛ التقاطع الوحيد وظيفي (الاعتماد يفتح النشر، الحظر يغلق المتجر).
2. **حالة المتجر تتصدر كل شيء عند التاجر:** غير معتمد / معتمد غير منشور / منشور / صيانة / معلّق — تحدد ما يُتاح من إجراءات، ويجب أن تكون مرئية دائماً. **[توصية]**
3. **المعاينة المعزولة (1.3.5)** تحتاج تمييزاً بصرياً واضحاً عن الموقع الحي كي لا يظن التاجر أن تغييراته منشورة — يُحسم شكله في مرحلة التصميم.
4. **الموظفون يرون ملاحة مقلّصة** بحسب صلاحياتهم (1.5.8) — البنية أعلاه هي الحد الأقصى (التاجر المالك).
5. **[سؤال مفتوح]** لا يوجد في متطلبات لوحة التاجر بند لعرض باقته الحالية أو ترقيتها، رغم أن الباقات تُدار إدارياً — فجوة ملاحية يجب حسمها قبل اعتماد البنية النهائية.

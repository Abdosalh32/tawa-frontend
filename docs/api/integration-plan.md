# خطة ربط الفرونت بالباكند — النسخة المكيَّفة على مشروع توا

> المرجع: خطة الربط التي أقرّها المالك (٧ مراحل ببوابات اختبار).
> هذه الوثيقة تسجّل **ما تغيّر عن نص الخطة ولماذا**، وحالة كل مرحلة، ونتائج البوابات.

## ١) تكييف الستاك — ما نفّذناه بدل ما ورد حرفياً

الخطة كُتبت على افتراض فرونت يُبنى من الصفر. مشروعنا قائم ومكتمل بصرياً بستاك أحدث،
فاتّبعنا **منطق المراحل والبوابات كما هو** وكيّفنا الطبقة التقنية:

| بند الخطة | ما نفّذناه | السبب |
|---|---|---|
| React 18 | **React 19** (قائم) | تنزيل إصدار قائم يكسر المشروع بلا مقابل |
| `npm create vite` لمشروع جديد | المشروع القائم | ٤٠+ شاشة مبنية ومراجَعة بصرياً |
| react-router-dom v6 | **react-router 8.3** (قائم) | المكتبة نفسها بإصدار أحدث؛ المسارات تعمل |
| TailwindCSS + RTL | **نظام تصميم بـ CSS خام ورموز دلالية** (قائم) | مبني ومُدقَّق في `TAWA_ART_DIRECTION.md`؛ Tailwind يعيد كتابة كل شيء بلا ربح |
| Axios بنسخة مركزية | ✅ كما هو | نموذج المعترضات يطابق ما تطلبه الخطة |
| TanStack Query v5 | ✅ كما هو | حالة الخادم والكاش وإعادة المحاولة |
| react-hook-form + zod | **مؤجَّل** | النماذج القائمة تتحقق محلياً وتعرض الأخطاء عبر `Field/Input`؛ خرائط أخطاء 422 تدخل الحالة نفسها. يُعاد النظر إن ظهرت نماذج معقّدة |
| ملفات `.js` | **TypeScript** | المشروع strict؛ الأنواع تمنع انحراف العقود |
| `pages/` و`api/` و`context/` | `src/lib/` للطبقة + بنية المزايا القائمة | البنية الحالية بالمزايا (features) وليست بالصفحات |

**ما لم يتغيّر:** مرحلة واحدة في كل مرة · بوابة اختبار قبل التالية · لا كود لمرحلة لاحقة ·
commit لكل مرحلة · عرض `message` القادمة من الخادم كما هي بلا اختراع نصوص.

## ٣) ما بُني في المرحلة ١

| الملف | الدور |
|---|---|
| `src/lib/env.ts` | `API_BASE_URL` من `.env.local` بافتراضي آمن |
| `src/lib/auth-token.ts` | توكن Sanctum في `sessionStorage` + اشتراك React |
| `src/lib/errors.ts` | `extractError` → `{ status, kind, message, fieldErrors }` |
| `src/lib/apiClient.ts` | نسخة Axios وحيدة + المعترضان + `apiGet/apiPost/apiPut/apiDelete` |
| `src/lib/queryClient.ts` | إعادة المحاولة لأخطاء الشبكة والخادم وحدها |
| `scripts/api-gate.mjs` | بوابة المرحلة ٠/١ على خادم حقيقي |
| `scripts/interceptor-check.mjs` | فحص الطبقة على خادم وهمي محلي — لا يحتاج Laravel |

**قرارات صغيرة اتُّخذت أثناء البناء:**

1. **المعترض يرفض بـ`ApiError` مترجَم** لا بخطأ Axios خام — فتتعامل كل الشاشات مع شكل واحد.
2. **معالج 401 قابل للحقن** (`setUnauthorizedHandler`): يسجّله `ApiSessionBridge` في `App.tsx`
   ليستعمل تنقّل الراوتر بدل إعادة تحميل الصفحة، مع احتياط `location.assign` قبل التسجيل.
3. **`sessionStorage` لا `localStorage`**: الجلسة تنجو من تحديث الصفحة (بند البوابة) وتموت
   بإغلاق التبويب — أنسب لجهاز مشترك.
4. **إعادة المحاولة انتقائية**: 4xx لا يُعاد (نتيجته لن تتغير ويؤخّر ظهور الخطأ).
5. **أخطاء الحقول بمسار الباكند نفسه** (`shipping_address.city`) بلا إعادة تسمية.

### نتيجة بوابة المرحلة ١ (خادم وهمي محلي)

## ٤) ما يوقف المرحلة ٠ (يحتاج قرار المالك)

1. **باكند توا غير مشغَّل**، و**المنفذ 8000 مشغول بمشروع آخر** على الجهاز
   (`~/Desktop/ph app` — صيدلية النقاء). فحص `/api/health` يعيد 404 من ذاك المشروع لا من توا.
2. **نسختنا من الباكند للقراءة فقط** بأمر صريح («دون أن تعدّل أو تلمس شيئاً فيه»)، وتشغيلها
   يتطلب `composer install` و`.env` و`migrate --seed` — وكلها تكتب داخلها.

الخيارات: يشغّله المالك بنفسه على منفذ حرّ · أو نأخذ **نسخة تشغيل منفصلة** بلا مساس بالأصل ·
أو ننتظر خادماً مشتركاً. بعد التشغيل: `npm run gate:api -- <العنوان>` يفتح البوابة أو يرفضها.

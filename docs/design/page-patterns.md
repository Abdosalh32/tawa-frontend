# أنماط الصفحات (Page Patterns) — منصة توا

> أنماط قابلة لإعادة الاستخدام على مستوى الصفحة، تبني على `design-system-foundations.md` و`component-inventory.md`. توثيق فقط.
> لكل نمط: التسلسل الهرمي، المناطق، موضع الإجراء الأساسي، الاستجابة، والقرارات المعلّقة.

---

## P1 — تصفح الستورفرونت (الرئيسية والتصنيفات ونتائج البحث) 🛍

**التسلسل:** شريط علوي (شعار + بحث + سلة/تتبع) ← شريط تصنيفات أفقي ← أقسام الرئيسية بترتيب التاجر (1.3.4) أو رأس تصنيف/نتائج ← شبكة المنتجات ← فوتر (سياسات + «متجر على منصة توا»).

**المناطق:** الرأس ثابت الالتصاق؛ الفلاتر (تصنيف، سعر، لون، مقاس 2.1.3 – 2.1.4) عمود يمين المحتوى في المكتبي؛ الشبكة 2 أعمدة هاتف → 4 مكتبي.

**الإجراء الأساسي:** «أضف إلى السلة» على البطاقات؛ لا زر أساسي آخر ينافسه في مساحة التصفح.

**الاستجابة:** الفلاتر Bottom sheet في الهاتف بزر «تصفية (عدّاد)»؛ الترقيم يصبح «عرض المزيد».

**الحالات:** لا نتائج بحث/فلترة ← فارغة-بفلتر؛ متجر بلا منتجات منشورة ← فارغة أنيقة بشعار التاجر؛ متجر غير منشور ← صفحة الصيانة (1.2.5).

---

## P2 — صفحة المنتج 🛍

**التسلسل:** مسار تنقل ← عمودان: معرض الصور (يمين) / كتلة القرار (يسار): الاسم، SKU، السعر (+مشطوب)، المتغيرات، مؤشر التوفر، الكمية + «أضف إلى السلة» ← أقسام قابلة للطي (وصف كامل، سياسات، شحن 2.1.5) ← «منتجات مشابهة» **[توصية]**.

**قواعد الكتلة الحاسمة:** المتغير غير المتوفر يظهر معطّلاً مشطوباً لا مخفياً؛ مؤشر التوفر بالأرقام عند الانخفاض («تبقى 5 قطع») **[توصية من وثيقة التحليل]**؛ تغيير المتغير يحدّث السعر والصورة والتوفر فوراً.

**الإجراء الأساسي:** «أضف إلى السلة» — وحيد وبارز، يلتصق أسفل شاشة الهاتف مع السعر.

**الاستجابة:** الهاتف عمود واحد: معرض بالسحب ← كتلة القرار كاملة فوق خط الطي ← التفاصيل.

**معلّق:** ظهور معلومات الشحن في الصفحة — **Pending product decision (D1)**.

---

## P3 — السلة والـ Checkout (نمط Placeholder) 🛍

**التسلسل:** Stepper (السلة ← الشحن والدفع ← التأكيد) ← محتوى الخطوة + ملخص طلب ثابت (عناصر، مجموع، شحن، خصم، إجمالي).

**المناطق:** السلة: قائمة عناصر (صورة، اسم، متغير، سعر، كمية ±، حذف ✕) بتحقق فوري من المخزون (2.2.2)؛ الشحن: نموذج عنوان وهاتف ومكان استلام (2.2.5)؛ الدفع: بطاقتا راديو (كاش افتراضاً / بطاقة) (2.2.7)؛ التأكيد: شاشة نجاح برقم التتبع `type.display` + زر نسخ + «احتفظ بالرقم» (M4).

**الإجراء الأساسي:** زر متابعة واحد لكل خطوة، بصيغة فعل محدد («إتمام الشراء»، «تأكيد الطلب»)؛ يلتصق أسفل الهاتف فوق الملخص المطوي.

**الاستجابة:** الملخص جانبي مكتبياً، مطوي قابل للفتح أعلى المحتوى في الهاتف.

**معلّق:** سطر الشحن وقيمته **(D1)** · شاشة معاملات البطاقة وسلوك الفشل **(D2)** · سلوك انتهاء حجز الـ 15 دقيقة (الافتراض المؤقت: إعادة تحقق صامتة عند التأكيد مع رسالة نقص واضحة) **(D8)** · حقل كود الخصم **(D9)**. النمط Placeholder حتى حسم D1/D2.

---

## P4 — نظرة عامة على لوحة التاجر 🏪

**التسلسل:** شريط حالة المتجر إن لزم (غير معتمد/غير منشور/معلّق) ← ترحيب + تاريخ ← صف بطاقات مؤشرات (≤4: مبيعات اليوم، طلبات جديدة، مخزون منخفض…) ← صف ثنائي: مخطط بسيط / قائمة «يحتاج انتباهك» ← جدول أحدث الطلبات المختصر.

**المبدأ:** الشاشة تجيب في ثلاث ثوانٍ: هل متجري سليم؟ وما الذي يستدعي تدخلي؟ كل بطاقة تنقل لشاشة التفصيل.

**الإجراء الأساسي:** «+ منتج جديد» في رأس الصفحة.

**الاستجابة:** البطاقات تتراص عموداً؛ المخطط يُبسَّط أو يؤجَّل أسفل القائمة التشغيلية في الهاتف.

**ملاحظة:** محتوى النظرة العامة **[توصية]** — لا بند «لوحة إحصائيات» صريحاً في المتطلبات.

---

## P5 — إدارة القوائم عند التاجر (منتجات، مخزون، طلبات، خصومات) 🏪

**التسلسل:** رأس (عنوان + عدّاد + إجراء أساسي) ← تبويبات حالة بعدّادات حيث تلزم (الطلبات 1.5.2) ← شريط أدوات (بحث + فلاتر + تبديل عرض إن وجد) ← جدول/شبكة ← شريط إجراءات جماعية عند التحديد ← ترقيم.

**قواعد:** الحالة دائماً شارة من القاموس الموحد؛ الأرقام الحرجة (متاح للبيع، إجمالي) `type.numeric`؛ إجراءات الصف في ⋮ (تعديل، أرشفة 1.4.5…)؛ التحرير الموضعي للمخزون (1.4.10) من الجدول مباشرة.

**الإجراء الأساسي:** إنشاء الكيان («+ منتج جديد»، «+ خصم جديد») في الرأس ثابتاً.

**الاستجابة:** الجدول بطاقات صف في الهاتف (هوية + حالة + رقم حرج + إجراء واحد).

**معلّق:** أعمدة حالة الدفع **(D2/G7)** · قائمة الخصومات تصمم بعد حسم آلية التطبيق **(D9)**.

---

## P6 — إنشاء/تعديل عند التاجر (نموذج المنتج نموذجاً) 🏪

**التسلسل:** رأس (رجوع + العنوان + حالة الحفظ) ← عمود محتوى رئيسي: بطاقات مجموعات (أساسية، صور، تسعير ومخزون، متغيرات 1.4.6 – 1.4.8) ← شريط جانبي: بطاقات الحالة (منشور/مسودة)، المخزون الصافي (الكلي/المحجوز/المتاح 1.4.9)، حد التنبيه (1.4.12) ← شريط حفظ سفلي ثابت (حفظ أساسي، حفظ كمسودة شبح، إلغاء نصي).

**قواعد المتغيرات:** مفتاح تفعيل ← تعريف محاور بـ Chips ← جدول تركيبات مولّد آلياً بتحرير موضعي (سعر/كمية/صورة/SKU لكل تركيبة)، وحذف التركيبة قابل للتراجع قبل الحفظ (يحمي من تعارض G8).

**الإجراء الأساسي:** «حفظ» في الشريط السفلي الثابت — لا يغيب عند التمرير.

**الاستجابة:** الشريط الجانبي ينضم أسفل المحتوى في الهاتف؛ إدخال المتغيرات تجربة مكتبية بالأساس (VD4).

---

## P7 — الطابور والمراجعة عند المدير 🛡

**التسلسل:** قائمة الطابور (تبويبات حالة بعدّادات + جدول بعمر الطلب «منذ يومين») ← شاشة مراجعة: رأس هوية (الاسم + شارة الحالة + الوقت) ← عمودا سياق: البيانات / الوثائق بعارض تكبير (م.1.3.1) ← **شريط قرار ثابت أسفل الشاشة**: اعتماد (نجاح) / طلب استكمال **[توصية]** / رفض (خطر).

**قواعد:** القرار لا يُتخذ من القائمة مباشرة — المرور بشاشة المراجعة إلزامي؛ الرفض والحظر بحوار سبب إلزامي يوضح ظهوره للتاجر (م.1.3.3)؛ كل قرار يذيَّل بـ«يُسجَّل في سجل التدقيق».

**الإجراء الأساسي:** «اعتماد وتفعيل» — لكن بصرياً بنفس وزن «رفض» تقريباً: القراران متكافئا الجدية.

**الاستجابة:** الاطلاع هاتفياً ممكن؛ أزرار القرار تبقى بتأكيدات كاملة (لا Swipe).

**معلّق:** محتوى الوثائق المعروضة ومتى تُرفع **Pending product decision (D3)** — النمط يصمَّم بعارض وثائق عام حتى الحسم.

---

## P8 — جدول البيانات وصفحة التفصيل عند المدير 🛡

**التسلسل (الجدول):** كنمط P5 بكثافة أعلى (متاجر م.1.3.6، فحص المنتجات م.1.3.8 بعرض شبكي لأن القرار بصري، سجل التدقيق م.1.3.13 كخط زمني مجمّع باليوم).

**التسلسل (التفصيل):** رأس هوية الكيان + شارات ← بطاقات المعلومات ← منطقة الإجراءات الرقابية معزولة بصرياً أسفل الصفحة (تعليق، حظر، فك) بحوارات التأكيد المدمر.

**قواعد سجل التدقيق:** قراءة فقط بلا أي زر تحرير؛ لكل قيد: مَن/ماذا/على مَن/متى/السبب؛ العمليات الحرجة موسومة أثقل (شريط جانبي `status.critical`).

**الإجراء الأساسي:** بحسب الشاشة — وفي الشاشات الرقابية البحتة قد لا يوجد إجراء أساسي، وهذا مقبول ومقصود.

**الاستجابة:** كثافة المدير تتنازل آخراً — الجداول تحتفظ بأعمدة أكثر مع تمرير أفقي داخل حاويتها في اللوح/الهاتف. **[توصية]**

---

## P9 — الإعدادات (تاجر ومدير) 🏪🛡

**التسلسل:** ملاحة أقسام داخلية (تبويبات أو قائمة جانبية ثانوية: عام، النطاقات، اللغة، النشر، الملف الشخصي والأمان 1.2.2 – 1.2.5، 1.5.6) ← لكل قسم بطاقات مجموعات بحفظ لكل بطاقة أو حفظ سفلي موحد (يُقرَّر بالتنفيذ — **[توصية]** حفظ لكل بطاقة).

**قواعد قسم النشر:** بطاقة الحالة الحالية الكبيرة + Checklist متطلبات النشر (اعتماد، منتجات، سياسات 1.2.4) بعلامات ✓/✗ ← زر النشر يتفعّل باكتمالها؛ «إيقاف استقبال الطلبات مؤقتاً» بحوار يشرح صفحة الصيانة وبقاء الطلبات قابلة للإدارة (1.2.5).

**الإجراء الأساسي:** حفظ البطاقة المعنية؛ وأفعال النشر في قسمها حصراً.

**معلّق:** قسم الوثائق **(D3)** · قسم الاشتراك **(D4)** · إدارة الشحن إن أصبحت إعداد تاجر **(D1)**.

---

## P10 — التأكيد المدمر + الفارغ/التحميل/الخطأ (أنماط عرضية) 🌐

**التأكيد المدمر (ملزم موحداً):** حوار يشرح الأثر بجملة محددة بأسماء فعلية («سيُجمَّد حساب (سوق الخير) ويُغلق متجره مؤقتاً») + سبب إلزامي حيث نصّت المتطلبات + زر خطر بصيغة الفعل + التركيز الابتدائي على الإلغاء + لا إغلاق بنقر الخلفية. يسري على: إلغاء الطلب (1.5.5)، الأرشفة (1.4.5)، تعطيل موظف (1.5.9)، إلغاء النشر (1.2.5)، وكل القرارات الإدارية (م.1.3.3، م.1.3.4، م.1.3.9).

**التحميل:** Skeleton يطابق التخطيط القادم؛ الأزرار تتجمد بـ Spinner داخلي أثناء الحفظ؛ لا شاشة تحميل صمّاء كاملة.

**الفارغ:** ثلاثية (رسم + جملة + إجراء أول)؛ التمييز الصارم بين فارغة-حقيقية وفارغة-بفلتر.

**الخطأ وإعادة المحاولة:** الخطأ داخل حدود المنطقة الفاشلة؛ رسالة بما حدث وما العمل + «إعادة المحاولة»؛ أخطاء النماذج موضعية على الحقول مع ملخص أعلى النموذج عند تعددها **[توصية]**؛ فشل الإجراء الرقابي يعيد الحالة كما كانت مع التوضيح.
